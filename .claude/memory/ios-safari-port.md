The iOS Safari port is tracked in **GitHub issue #7**
(https://github.com/jazahn/focus-reader/issues/7). It was planned on 2026-10-04
around an in-repo Xcode project generated by `safari-web-extension-converter`;
on 2026-10-31 that was **superseded** by the packager route below, and the
cross-browser code changes landed in-tree as 0.2.2 (unreleased on both stores
at the time of writing).

**Distribution: App Store Connect → Users and Access → Xcode Cloud → Safari Web
Extension Packager.** Added at WWDC26. You upload the extension ZIP (the same
`dist/focus-reader-<v>.zip` that `tools/package.sh` builds for Chrome); Apple
builds the iOS container app server-side and pushes it to TestFlight. Requires
the paid Developer Program (the owner is enrolled). Xcode is only still needed
for native messaging, which we do not use. Consequences: no `safari/`
directory, no `MARKETING_VERSION` coordination, no move of shipping files into
`extension/`. Full walkthrough in `PUBLISHING.md` Part 2. iOS only for the
first release (owner's choice); macOS can be added later from the same ZIP.

**Why not the converter on this Mac:** macOS 14.7 + Xcode 16.2 can simulate
only iOS 18.2, Xcode 26 will not install on macOS 14, and the owner's iPhone 17
runs iOS 26.x, which Xcode 16.2 cannot deploy to. Safari 27 is not offered for
macOS 14 either; local Safari tops out at 26.6.1. A throwaway *macOS* wrapper
still builds fine with Xcode 16.2 (ad-hoc signed, `CODE_SIGN_IDENTITY="-"`) for
exercising the popup and permission flow; the recipe is in `PUBLISHING.md`
Part 2 §5. Note `--no-copy-resources` is **not** a real converter flag — the
2026-10-04 notes and the issue text were wrong; reference-in-place is the
default and `--copy-resources` is the opt-in.

**Safari behaviour differences that are by design** (see
[[safari-highlight-support]] for the rendering one):

- Emphasis is a faint `background-color` tint (`--focus-tint`, set by
  `content.js` when `navigator.vendor` is Apple's), not thicker glyphs.
- `<all_urls>` grants nothing on iOS; permission is per site on first tap, and
  until then `tabs.query` hides the tab URL. `popup.js` checks
  `permissions.contains({origins:['<all_urls>']})` to tell "not allowed yet"
  from "page cannot be modified".
- `storage.sync` does not sync via iCloud; never promise cross-device settings.
- `commands` does not exist on iOS; `background.js` guards the listener.
- Toolbar icons are template images, so active/muted is an opacity difference.
- The popup is a full-width sheet on iPhone (viewport meta + `pointer: coarse`
  width override in `popup.*`).
